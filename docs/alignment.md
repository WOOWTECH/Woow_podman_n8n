## HA to Podman mapping

| Capability | HA add-on | Podman package |
| --- | --- | --- |
| Editor, REST API, webhooks, instance-level MCP | n8n 2.43.6 | Same upstream version 2.43.6 |
| Code nodes | Matching 2.43.6 JavaScript and Python runners in the add-on container | Matching 2.43.6 runners in a separate container; native Python enabled |
| Module imports | `NODE_FUNCTION_ALLOW_BUILTIN=*`, `NODE_FUNCTION_ALLOW_EXTERNAL=*`, `N8N_RUNNERS_STDLIB_ALLOW=*`, `N8N_RUNNERS_EXTERNAL_ALLOW=*` | Same runner configuration, with only the workdir changed to `/home/runner` |
| Encryption and storage | SQLite and `/config` in an HA backup | PostgreSQL 16 and `n8n_n8n_data` volume; backup includes DB dump, encryption key, secrets and units |
| Broker token | Per-installation random file; broker binds to loopback | Per-installation Podman secret mounted as a file in n8n; separate runner receives it as a launcher secret; broker binds to the private Podman network, with no published port |
| Workflow environment access | `$env` enabled; Supervisor tokens removed before n8n starts | Example enables `$env`; DB password and broker token are mounted as files rather than n8n environment values |
| Storage migration and config permissions | `N8N_MIGRATE_FS_STORAGE_PATH=true`; enforce settings file permissions | Same settings in the n8n Quadlet |
| Public URL and cookies | Direct HTTP, HA Ingress and Cloudflare Tunnel; secure cookies disabled for HTTP | Loopback or LAN publish, Cloudflare Tunnel or reverse proxy; `--public-url` sets editor/webhook URLs and proxy hops; cookies follow the selected HTTP/HTTPS setup |
| Health and stop | Supervisor watchdog and 60-second stop timeout | n8n/runner health checks, 900-second migration grace, n8n stops before runners, 60-second container stop timeout |

The HA ingress nginx, Supervisor API and sidebar integration are HA-only. The HA image also includes Redis for workflows using `localhost:6379` and shell utilities such as Python 3.14, Bash, curl and jq for Execute Command nodes. This Podman package uses the upstream n8n image and does **not** supply those extra binaries or an embedded Redis instance. Its optional Valkey service is a private queue broker at `n8n-valkey:6379`, not a workflow-local `localhost:6379` replacement. The current PaaS deployment and the external chart's optional features are compared below.

## Optional Podman queue profile in this change

`EXECUTIONS_MODE=queue` adds a password-protected Valkey 8.1.11 with a persistent AOF volume, a single n8n 2.43.6 worker with configurable concurrency (default 5) and its own n8nio/runners 2.43.6 launcher. The existing main process and runner remain. `N8N_QUEUE_WEBHOOK_PROCESSOR=true` additionally starts an n8n webhook process on `WEBHOOK_PORT` (15679 by default); a reverse proxy must route production webhook paths to it. Once that route works, `N8N_QUEUE_DISABLE_MAIN_WEBHOOKS=true` sets `N8N_DISABLE_PRODUCTION_MAIN_PROCESS=true` on the main unit only. All n8n processes share the credentials encryption key in `n8n_n8n_data` but write separate event logs; queue mode uses database binary storage. There is one worker, with no configurable replica count in this Podman profile.

The installer renders the selected units and validates them with Podman Quadlet 4.9.3. A topology change triggers a cold backup before stopping processes; queue backups include both a PostgreSQL dump and Valkey volume/secret. Restore and upgrade rollback handle Valkey state. `tests/queue-integration.py` ran in isolated rootless Podman containers on 2026-11-09: PostgreSQL, Valkey authentication, main and worker readiness, both runner registrations, webhook processor health, a production webhook request and successful queued Code-node execution all passed. The test removed its own containers, volumes, network and secrets. The production instance on this host remains in regular mode; no reverse-proxy routing or live queue cutover was performed.

Current platform Gitea `main` (`e68d2f2`, committed 2026-06-25) has its n8n template at `src/data/cloud_app_templates.xml:56-100`. It references the external 8gears OCI chart without pinning version `2.0.1`, requests a 2Gi SQLite PVC, and enables an n8n MCP sidecar. Those settings differ from the October live releases: chart `2.0.1`, 10Gi PVC and no MCP sidecar. The exact platform source commit that generated the live Helm values remains unknown.
